# Opus 級モデルへの指示書 — 設計判断を伴うタスク

前提: [`../../CLAUDE.md`](../../CLAUDE.md) の共通ガードレールを読んでいること。
本書は**判断の余地が大きいタスク**（新機能・研究調査・ADR 起票・アーキテクチャ変更・
ユーザー方針決定後の STL インポート等）を担う際の作法を定める。Sonnet 級には
[`sonnet-instructions.md`](sonnet-instructions.md)（手順書型）を使う。

## 1. あなたに期待される判断

Kado は「機能を足す」より「**足すべきかを問う**」を重んじるプロジェクト。
新機能は `docs/feature-triage.md` §1 の2軸で自己審査してから実装する:

1. **代替可能性**: 既存の演算子/ツールの組み合わせで実現できないか。できるなら
   原則不要（例外は「AI が毎回組み合わせる手間を省く正当な糖衣構文」＝ `rounded_box`）。
2. **規律適合**: 決定性・std-only・恣意的閾値なし・リソース上限・応答サイズを守れるか。
   一つでも破るなら見送り。

判定は socratic-review に**問いの形で**残す（結論だけでなく、なぜ採用/却下したか）。

## 2. 数学的正当化の水準

幾何・数値の追加は「動くから入れる」ではなく、**性質を証明して入れる**:

- **好例（採用）**: 面取りブーリアン（問285）。IQ/hg_sdf の閉形式を採り、
  「hard 演算の下界/上界であること」「k→0 で hard に収束すること」「丸フィレットと
  幾何的に別物であること（代替不可能性）」をテストで証明。かつ「表面厳密・内部近似」
  という制約を **SPEC の非目標節に誠実に明記**した。
- **対例（見送り）**: ねじ/ヘリカル（問270）。「Lipschitz 定数が半径で発散し、
  閉形式で有界な厳密解が文献上存在しない」という数学的限界を根拠に見送った。
- 教訓: **できないことを隠さず、制約を文書化する**。近似なら近似と書く。

## 3. 最新研究・外部情報の扱い

「最新論文/情報を調べて改善点を洗い出す」系のタスクでは:

- 出典（arXiv 番号・仕様 URL）を socratic エントリに**実在確認の上**記載する。
- 研究動向を Kado の要件（決定性・std-only）に**翻訳**する。例: ニューラル/
  微分可能メッシュ抽出（SDF-CWF 等）は品質軸が別で、MT 維持判断（ADR-001）を
  崩さない——と結論づける。むやみに追従しない。
- 実装に落とすのは「規律を崩さず具体的な不足を埋める」ものだけ（v151 の
  問285-288 が範例。MCP 版追従・PNG フィルタ・軸目盛り・面取り）。

## 4. 検証水準（Opus タスクは特に厳しく）

- **外部独立検証**: 自前実装の出力は Kado 以外の実装で検証する。PNG は Python
  `zlib` で復号し CRC 照合、GLB は外部 glTF パーサ、3MF は `zipfile.testzip()`
  （`docs/SPEC.md` §10）。「自分の理解で自分をテスト」は不十分。
- **実バイナリ E2E**: MCP に関わるなら `tests/mcp_workflow.rs` の型で実 `kado mcp` を
  叩く。ユニット緑で完了としない（問292 の教訓）。
- **決定性の再確認**: 新しいエンコード/抽出経路は「2回実行バイト一致」を固定。

## 5. ADR を起こす基準

以下は `docs/adr/` に ADR を追加してから実装する:
- カーネル/抽出アルゴリズムの変更（ADR-001 の範囲）。
- GUI・ネットワーク・永続化など「非目標」を動かす提案（原則却下だが、検討の記録は残す）。
- 外部 crate の導入（原則禁止・SPEC 個別承認が要る）。

## 6. STL インポート（問296 で検証専用として実装済み）

`docs/feature-triage.md` のかつての唯一の未解決候補。問296 で**保守的な検証専用
設計**として実装した——`validate-stl` CLI コマンドが binary STL を読み込み DFM
検証するが、SDF シーン正本には決してしない（ADR-001 保存）。参考実装として:
- `io::stl::decode_binary`: 厳格検証（長さ不一致・ASCII・非有限・上限超過を確保前拒否）。
- mesh→SDF 再構成は**しない**（Kado が避けてきた数値破綻を招くため・非目標のまま）。
- MCP には出さない（読み取り攻撃面を増やさない）。CLI 専用でファイル読み込みを局所化。
- SDF として再編集する用途を将来求められても、非目標である旨を説明して実装しない。
