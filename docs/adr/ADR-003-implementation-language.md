# ADR-003 — 実装言語・ランタイム: Rust

> 状態: 採択 ｜ 日付: 2026-06-11 ｜ 文脈: Plan.md §4 Phase 0 / 付議事項⑤（問3）

## 文脈

Plan.md は実装言語に依存する横断的制約を多数課している:

- **単一自己完結バイナリ**（実行時外部依存ゼロ、静的リンク許容 — 問4）
- **決定的出力**（同一バイナリ・同一arch内バイト同一 — 問5）
- **高性能 + SIMD/並列**（SDF評価・メッシュ抽出・ラスタライザ）
- **DSLサンドボックス**（コード実行経路の封じ込め — リスクE）
- **GILなし**（v3.0のPython配布痛・GIL律速の反省）
- 起動 ≤100ms / コア小・保守性

候補: Rust / C++ / Zig / Go。

## 決定

**Rust を採用する。**

## 根拠

| 制約 | Rust | C++ | Zig | Go |
|------|------|-----|-----|----|
| 単一静的バイナリ | ◎ (muslターゲットで完全静的) | ○ | ◎ | ◎ (ただしGCランタイム同梱) |
| 決定性 (FP/縮約順序制御) | ◎ (fast-math既定なし・明示制御) | △ (-ffast-math事故りやすい) | ○ | △ (mapイテレーション等) |
| SIMD/並列 | ◎ (std::simd/portable_simd・スレッド安全を型で保証) | ◎ | ◎ | △ |
| サンドボックス実装 | ◎ (自前DSL・所有権でリソース境界明確) | ○ | ○ | ○ |
| GCなし/起動速度 | ◎ | ◎ | ◎ | △ (GC・ランタイム) |
| メモリ安全 (大規模幾何コード) | ◎ | ✕ | △ | ◎ |
| エコシステム/CI/SBOM | ◎ (cargo audit/cargo-deny) | △ | △ | ○ |

決め手:
1. **決定性**: fast-mathが既定で無効、FP縮約順序を制御できる。問5の「同一arch内バイト同一」を最も自然に達成。
2. **メモリ安全 × 高性能の両立**: 幾何カーネルは複雑なポインタ/インデックス操作の塊。GCなしで安全を型で保証できるのはRustのみ。Goはランタイム同梱で「実行時外部依存ゼロ」の精神に劣る。
3. **単一静的バイナリ**: `x86_64-unknown-linux-musl` 等で完全静的リンク。
4. **サプライチェーン**: `cargo-deny` / `cargo audit` でSBOM・脆弱性ゲートを CI 化（Plan §5 ci.yml）。

## 帰結

- 依存方針（問4）: **コア（src/core, extract, render, io, script）は std のみ**で実装し外部crateを持ち込まない。テスト・開発補助に限り devDependencies を許容。何を std 以外に許すかは SPEC で個別承認制。
- 決定性方針（問5）: `-ffast-math`相当を使わない / FP縮約は固定順序 / 並列リダクションは決定的（ツリー縮約の順序固定）/ 超越関数は std の libm 実装に固定し、クロスプラットフォームは数値同等but非ビット同一と明示。
- リリースは musl 静的リンクを既定ターゲットとする。

## 却下案

- **C++**: メモリ安全性なし。大規模幾何コードでの不変条件維持コストが高く、決定性も -ffast-math 事故が起きやすい。
- **Zig**: 言語・エコシステムが未成熟（1.0前）。長期保守の安定性に欠ける。
- **Go**: GC・ランタイム同梱が「実行時外部依存ゼロ・起動≤100ms・決定性」の精神と相性が悪い。
